论文阅读真正费时间的地方，往往不只是读懂某一篇论文。每天从 Hugging Face、arXiv 等来源找新论文，判断哪些值得看，精读之后再整理成能够长期检索的笔记，这些步骤加起来才是完整的工作量。

最近我接触并参与了开源项目 [dailypaper-skills](https://github.com/huangkiki/dailypaper-skills)。它把这套流程做成了一组 Claude Code skills：平时只需要说“今日论文推荐”或“读一下这篇论文”，后面的抓取、筛选、阅读和笔记整理会按照约定的流程运行。截至 2026 年 9 月 16 日，这个项目在 GitHub 上已经获得 1,232 Stars。

## 它解决了什么问题

dailypaper-skills 不是单独的论文总结提示词，而是一条可以重复运行的论文工作流。

“今日论文推荐”大致会经过三个阶段：

1. 从 Hugging Face Daily、Trending 和 arXiv 获取候选论文，根据用户关心的研究方向打分和去重；
2. 对候选论文做进一步判断，分成“必读”“值得看”和“可跳过”，生成当天的推荐页；
3. 对重点论文调用阅读流程，生成结构化笔记，补充概念链接，并刷新 Obsidian 目录页。

最终内容仍然是保存在本地的 Markdown 文件。每日推荐进入 `DailyPapers`，论文笔记按照研究方向进入 `论文笔记` 下的分类目录，相关概念则进入单独的概念库。已经在使用 Zotero 的人，也可以从 Zotero 标题或分类开始批量处理论文。

我喜欢这种设计的一点，是它没有把所有工作塞进一次超长对话。抓取、点评和深度阅读被拆成不同阶段，中间结果落到文件中。某一步失败时更容易定位，后续也可以只重新执行其中一段。

## 为什么值得试试

这套项目比较适合已经有明确研究方向，并且希望长期积累论文笔记的人。

首先，它把“发现论文”和“精读论文”分开了。候选论文会先经过关键词和领域偏好的初筛，再由模型做内容判断，不需要一开始就对每篇论文投入完整的阅读成本。

其次，它使用 Obsidian 和普通 Markdown 保存结果。即使以后不再使用这套 skill，已经生成的推荐、论文笔记和概念链接仍然可以继续阅读和迁移，不会被锁在某个在线服务里。

项目还提供了一个基于 FastAPI 的 Web Viewer，可以在浏览器中查看每日推荐、论文笔记、概念库和 GitHub Trending，也支持搜索、Wikilink 和 LaTeX 渲染。对于不想一直停留在 Obsidian 界面里的人，这个轻量入口很实用。

## 我遇到的 Web Viewer 问题

项目的论文阅读流程会按照研究方向保存笔记，例如：

```text
论文笔记/
├── 3-机器人策略/
│   └── CategorizedMethod.md
├── _概念/
└── _待整理/
    └── InboxMethod.md
```

但当时 Web Viewer 的论文列表只扫描 `_待整理`。一篇论文经过整理、移动到正式分类后，反而会从网页列表、搜索结果和 Wikilink 索引里消失。生成流程和展示流程对“论文笔记在哪里”有两套不同理解，这是一个很典型的数据发现范围不一致问题。

直接把扫描目录从 `_待整理` 改成整个 `论文笔记` 还不够。这个根目录下面同时包含概念库、自动生成的目录页和可能重名的论文笔记。如果全部当成论文展示，会产生新的混乱。

## 修复思路

我在修复中增加了统一的论文发现逻辑，让列表、详情、搜索和 Wikilink 索引使用同一组结果。

扫描会递归遍历论文笔记根目录，同时排除：

- `_概念` 下的概念笔记；
- 隐藏目录；
- 由目录生成脚本创建的 MOC 索引文件；
- 指向论文笔记根目录之外的文件链接。

分类目录中可能存在同名文件，所以不能继续只用文件名作为页面标识。我改用相对论文根目录的无后缀路径作为稳定 ID，例如：

```text
_待整理/InboxMethod
3-机器人策略/CategorizedMethod
```

前端的论文列表、搜索结果和 Wikilink 会携带这个 ID，后端详情接口再从统一的发现结果中解析对应文件。裸文件名链接仍然保留兼容，但只有在它能够唯一对应一篇论文时才会生效；如果两个分类中存在同名笔记，就必须使用完整相对路径，避免静默打开错误内容。

我还为这些行为补了回归测试，覆盖分类笔记发现、概念与 MOC 排除、详情读取、路径逃逸、同名文件歧义和搜索结果 ID。相关修改通过 [PR #16](https://github.com/huangkiki/dailypaper-skills/pull/16) 提交，并于 2026 年 9 月 16 日合并。我也因此正式成为了这个项目的贡献者。

## 如何开始使用

项目本身已经提供了完整的安装和配置说明，最稳妥的方式是直接查看仓库的 [README](https://github.com/huangkiki/dailypaper-skills#readme)。基本流程是把仓库中的 skills 安装到 Claude Code 的 skills 目录，再配置 Obsidian Vault、研究关键词以及可选的 Zotero 路径。

配置完成后，可以先从最小的两个入口开始：

```text
今日论文推荐
读一下这篇论文 https://arxiv.org/abs/xxxx.xxxxx
```

建议先检查生成目录、关键词权重和一两篇笔记的质量，再决定是否批量运行。项目默认不会自动提交或推送 Obsidian 仓库，这个保守设置值得保留；确认自己的目录和输出符合预期后，再考虑开启额外自动化。

## 总结

dailypaper-skills 最有价值的地方，不是让模型替人读完所有论文，而是把每天都会重复的发现、筛选、精读和归档步骤连接起来，并让结果继续留在本地知识库中。

如果你已经使用 Claude Code 和 Obsidian，也经常需要跟踪某个研究方向，这个项目值得试一遍。对我来说，这次贡献也不只是修复了一个页面列表：它让我真正沿着整条数据流检查了论文从生成、分类到检索和展示的过程，并把发现的问题变成了一个已经合并的改进。
